# Documentation-Chase Mode

A single documentation clone reads source code and produces markdown documentation. The work queue is pre-populated at cast start by parsing the task description into individual documentation items.

## Usage

```bash
manta cast documentation-chase --task "Document modules: packages/manta-bus/src/state/registry.ts, packages/manta-cli/src/commands/cast.ts" --clones 1
```

## How It Works

1. At cast start, `DocChaseDispatcher.parseTaskIntoItems` extracts file paths from the task description
2. Each path becomes a separate work queue item for the documentation clone
3. The clone processes items one at a time via the daemon loop
4. After documenting each module, the clone broadcasts `docs_ready` with the file list
5. Cast ends when the work queue is empty and the clone is idle

## Scope Restrictions

- Output goes to `docs/api/`, `docs/arch/`, or `docs/generated/`
- Source files in `packages/` are read-only — the clone cannot modify them
- Every doc file starts with: `> Auto-generated by documentation-chase clone.`

## Broadcast Events

| Event | Sender | Payload |
|-------|--------|---------|
| `docs_ready` | documenter | `{ files, commit, summary }` |

## Skills

- `manta-doc-chase` — documentation clone instructions
- `manta-daemon-idle` — idle/resume protocol for daemon clones
